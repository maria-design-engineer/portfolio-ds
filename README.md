# ds

Дизайн-система сайта-портфолио в коде: библиотека компонентов и витрина Storybook. Отдельный репозиторий рядом с `app/`.

Библиотека отдаёт семь компонентов: `Button`, `Chip`, `Spin`, `TextArea`, `TextInput` и два продуктовых — `CaseCard`, `WhyPoint`. Вместе с ними едут токены, стили текста и шрифты.

## Требования

```
├─ Node 24.16.0 — на нём проект собран и проверен, эту же версию ставит автосборка
├─ npm 11.13.0
└─ интернет при установке зависимостей
```

Базы, сервера и файла `.env` у библиотеки нет.

## Установка с нуля

**1. Взять репозиторий.** Адрес — у владельца репозитория.

```
git clone <адрес репозитория> ds
cd ds
```

**2. Поставить зависимости по файлу замка.**

```
npm ci
```

Проверить: команда заканчивается без строк `ERR!`, появилась папка `node_modules`.

**3. Запустить витрину.**

```
npm run storybook
```

Проверить: терминал печатает адрес `http://localhost:6016/`, по нему открывается витрина с разделами «Обзор» и «Токены».

**4. Собрать пакет.**

```
npm run build
```

Проверить: в `dist/` лежат `ds.js`, `ds.css`, `index.d.ts` и папка `licenses`.

**5. Прогнать проверочные запуски.** → раздел «Проверочный запуск». Оба заканчиваются строкой «провалено 0».

## Команды

- `npm install` — зависимости по файлу замка `package-lock.json`
- `npm run storybook` — витрина, печатает локальный адрес
- `npm run build` — пакет в `dist/`: `ds.js` (ESM), `ds.css`, типы `.d.ts`
- `npm run build-storybook` — статическая витрина в `storybook-static/`
- `npm run check` — проверочный запуск окружения, см. ниже
- `node check-components.mjs` — проверочный запуск компонентов на собранном пакете, без браузера: поля в форме, сочетания состояний кнопки, подпись спина, пометка и слой пакета

## Проверочный запуск

`check-setup.mjs` проходит цепочку окружения — Node, точные версии, файл замка, установленное, сборка пакета, витрина — и печатает ожидание рядом с фактом, в конце итог числом. Запускать после переустановки окружения, на новой машине и когда надо отделить поломку окружения от поломки кода. `--no-build` пропускает сборку.

## Подключение к сайту

- `import { Button } from 'ds'` — компоненты; `import 'ds/styles.css'` — стили, один раз в корне сайта.
- Пакет помечен `'use client'`: компонент импортируется и в серверный компонент Next, правок на стороне сайта не нужно.

### Слой стилей

Все стили библиотеки, кроме шрифтов, лежат в слое `ds`. Класс сайта, переданный компоненту в `className`, перебивает стиль библиотеки без `!important`.

Порядок слоёв объявляет сайт, первой строкой своих стилей, до `@import`:

```css
@layer theme, base, ds, components, utilities;
```

`ds` стоит после `base` — сброс стилей Tailwind библиотеку не ломает — и до `components` и `utilities` — классы сайта её перебивают. Стили сайта вне слоёв сильнее любого слоя.

Переменные библиотеки начинаются с `--ds-`, классы — с `ds-`: с именами темы Tailwind они не пересекаются.

### Установка в сайт

Сайт ставит собранный пакет архивом релиза GitHub, не исходники: на машине библиотеку не собирают.

```
npm install https://github.com/<логин>/<репозиторий>/releases/download/v<номер>/ds-<номер>.tgz
```

Адрес архива лежит на странице релиза с тем же номером; файл замка сайта запоминает адрес и контрольную сумму. Новая версия библиотеки — новый тег здесь и правка этой одной строки в `package.json` сайта. В `package.json` библиотеки `react` и `react-dom` названы точной версией 19.3.0: сайт ставит ту же.

Версии зависимостей точные, без диапазонов: новая ставится правкой номера в `package.json` и повторной установкой.

## Витрина по публичному адресу

Витрина живёт на GitHub Pages: `https://<логин>.github.io/<репозиторий>/` — логин и имя репозитория смотри в `git remote -v`.

Публикует автосборка `.github/workflows/pages.yml`: запускается отправкой тега вида `v*`, ставит зависимости по файлу замка, собирает `storybook-static/` и выкладывает его. На адресе всегда стоит последний отправленный тег. Пересобрать без нового тега можно вручную со вкладки Actions. Версии шагов автосборки точные, как и в `package.json`.

Зелёный прогон не доказывает, что доехало: откройте адрес и убедитесь, что на нём нужный релиз.

## Релиз

Отправку выполняет владелец репозитория. Сначала номер версии в `package.json` — тот же, что у тега, без `v`; потом код; потом тег — он пересобирает витрину и прикладывает архив пакета к релизу.

```
git push origin main
git tag -a v<номер> -m "<что в релизе>"
git push origin v<номер>
```

Номер в `package.json` расходится с тегом — работа `release` автосборки падает с текстом о расхождении, витрина при этом пересобирается.

Проверить: `git ls-remote --tags origin` показывает новый тег; через три-пять минут публичный адрес после обновления страницы начисто показывает релиз, а на странице релиза лежит `ds-<номер>.tgz`.

До отправки код проходит ревью: оно смотрит только неотправленные коммиты.

## Как устроен проект

```
├─ src/index.ts — точка входа пакета: чего в ней нет, того для сайта не существует
├─ src/<Компонент>/ — компонент и его страницы витрины `*.stories.tsx`
├─ src/*.css — стили компонентов; `styles.css` собирает их в один файл
├─ src/tokens.css — переменные кита с приставкой `--ds-`, режим `Mobile` — окно уже 1024 px
├─ src/kit-styles.css — стили текста классами `ds-text-*`, тени, сетки
├─ src/fonts.css и src/fonts/ — шрифты Golos Text и Google Sans Code
├─ src/icons/ — реестр иконок из `@fluentui/svg-icons` и страница «Иконки»
├─ src/showcase/ — обзорные страницы `Desktop` и `Mobile`, помощники витрины
├─ public/licenses/ — тексты лицензий, едут в пакет и в витрину
├─ check-setup.mjs, check-components.mjs — проверочные запуски
├─ .github/workflows/pages.yml — автосборка по тегу: витрина на Pages и архив пакета к релизу
├─ dist/ — собранный пакет, в репозиторий не едет
└─ storybook-static/ — собранная витрина, в репозиторий не едет
```

Стек: Vite 8 в режиме библиотеки, React 19, TypeScript 6, Storybook 10, Base UI 1.8.

Источник вида и состава компонентов — UI-kit в Figma и его описание; они живут вне этого репозитория, у владельца.

## Лицензии

Чужое едет вместе со своей лицензией. Тексты лежат в `public/licenses/`, сборка кладёт их в `dist/licenses/` и в витрину.

```
├─ OFL-golos-text.txt — шрифт Golos Text, SIL OFL 1.1
├─ OFL-google-sans-code.txt — шрифт Google Sans Code, SIL OFL 1.1
└─ MIT-fluentui-system-icons.txt — иконки Fluent System Icons, MIT
```
